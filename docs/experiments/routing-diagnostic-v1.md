# Routing diagnostic v1：布局与输出额度开发验证

2026-10-28。用户已要求提高上限并按顺序迭代验证。O2-00 服务结束证据与 O2-01 新布局分别已提交。本协议用于 O2-02 / O2-03，独立于 O1；O1 的 256 上限、失败和历史未知不改写。

## 固定合同

矩阵：10 个开发任务、10 个已声明模板 family、两个目标能力各 5 个，2 repeats。八条件为 v1/v2 布局 ×256/512 输出额度 ×0/2 固定示例，**160 次生成**。先执行两个目标能力各一个任务的全部八条件，共 16 次，已包含在 160 次内。条件顺序按 seed `20261028` 轮转，所有数据、期望 JSON、策略版本和快照摘要在首次调用前冻结。

训练示例直接承接 O1 已核验的两条来源：核对原始请求视图、原始选择、JSON 验收与受约束 worker 的零模型调用证据，不重新生成示例。实例复制封闭且 checkpointed 的父数据库和 blob；旧 Run 不执行，原额度占用和历史成本保留，新 Run 用 `diag:` 前缀及独立事件流。

v2 保持原 system，只在末条 user 中加入当前视图。除这三个因素外，核心图、视图、示例池、模型、temperature、worker 与裁判相同；注册会重核条件标注与实际策略，拒绝混入额外差异。输入按同一冻结正文计数 ≤2,048，与返回实际用量核对；这仍是预检，输入硬上界未证明。

每个 Run 至多 1 次执行尝试、总计 30 秒、决策上限 28 秒；SDK 无自动重试。总派发时限为计划槽位数 ×30 秒加 300 秒收尾。剩余不足完整 Run 时停止领取，不把总截止强行压缩为最后一次短请求。unknown、计数/实际用量漂移、超额、模型身份异常、缺少服务结束元数据均停止；已占槽位不重发、不退款。

首 16 次完全没有合法 value 时停止，剩余分母保留。普通非法 JSON 与模型弃权均计为结果，不挑选成功重试。每个返回结果保存原始正文、结束原因、响应块类型和文本字节数；不保存隐藏推理正文或凭据。

## 评分与确认

报告按完整计划分母和 family 等权，分列合法 JSON、实际 worker 验收成功、误派、结束原因、用量与所有缺失。JSON 合法的模型弃权不算任务成功；服务 refusal 不算模型决策 JSON。清理工作区和资料后，必须从原始账本复算并与封存报告一致。

矩阵全部计量与结束证据完整后，合法 JSON ≥95%、成功 ≥90%、误派 ≤5% 的条件进入筛选。依次按成功率较高、额度较小、示例较少、已知总 token 较少、固定条件次序选择至多一个配置。没有配置满足则停止扩大实验。

确认阶段使用 20 个另外声明的开发任务（10 个 family ×2 变体），4 个关键任务，2 配置 ×3 repeats，**120 次**。候选固定后不再搜索，对照在首次确认请求前按以下规则固定：

1. 有示例候选：相同布局、相同额度、零示例。
2. v2 零示例候选：相同额度的 v1 零示例。
3. v1/512/零示例候选：v1/256/零示例，直接确认提高额度的改进。
4. v1/256/零示例胜出：未得到不同的改进配置，停止，不重复相同策略充当对照。

候选须合法 JSON ≥95%、实际成功 ≥90%、关键任务全过，并比固定对照成功率至少高 5 个百分点，才通过开发确认。只有示例候选通过才准备完整三臂；仅额度或布局改善不冒充示例/编译收益。

## 成本与资格

O1 历史 793 次、已知 304,045 input /174,841 output、未知用量 1 次永久单列。O2 开发最多 160+120=280 次，后续若另开完整三臂 750 次，改进链上限草案共 1,030 次；不会将开发成本从后续报告删除。现阶段登记只预留实际开发阶段的全部槽位，同时保留父实例的已占模型调用。计数 API、生成尝试与已知/未知费用分别记录，不把没有价格的调用或 CPU 成本写成免费。

`engineering` 只判断当前开发阶段；`totalUnknownUsageCallsIncludingHistory` 继续包含旧轮未知。全部资料为开发方可见，语义独立性和输入硬上界均 unverified。真实模式收益始终 inconclusive，fixture 为 not_evaluated；不创建 Candidate、正式 Evaluation、Promotion，不改变 activeGenome。

## 运行与证据

```bash
env PATH="/opt/homebrew/bin:$PATH" /opt/homebrew/bin/node \
  tests/experiments/run-diagnostic.ts --real --output NEW_DIRECTORY \
  --parent SEALED_O1_DIRECTORY --stage matrix \
  --claude-settings /path/to/explicit/settings.json
```

确认使用新的输出目录、`--parent SEALED_MATRIX_DIRECTORY --stage confirmation`。父轮必须完整、计量通过且有合格配置；不接受同策略确认或在途数据库。真实入口要求干净 Git，凭据只在内存使用。`--fixture` 运行完整规格的脚本模型/真实本地 worker 演练；`--report DIRECTORY` 离线核验，不派发请求。路径不可复用或覆盖。

工程验收包括：完整 160 槽位 fixture、首 16 次停止、计数超限不生成、正文/条件漂移拒绝、两个连接竞争、丢失响应、已知用量漂移、崩溃后部分成本保留及不重发、清理重开、原始正文篡改拒绝、跨阶段累计成本、512 对 256 的确认对照，以及拒绝把小 fixture 改标为完整 real。

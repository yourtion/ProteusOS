# 本体决策实验 v1：实施与验证规范

状态：**协议已冻结；E1–E4 已实现并通过工程验证（2026-09-22，含 D01–D15 场景与 M0–M2 回归）；真实模型调用未执行（缺凭据，`realModel=not_run`），E5 独立验证待验证负责人执行**。基准提交为 `c77188a`，协议 ID 为 `organism-decision-v1`。本文与 [ADR 0007](../adr/0007-organism-decision-experiment.md)组成开发交接合同；数值是本次实验预先选择的门槛，不是已经获得的结果，也不代表所有任务的通用标准。实现落点、命令、退出码与未验证条件见[执行说明](./organism-decision-v1-runbook.md)。

后续 agent 按本文分片实现并执行验证。无需重新设计 Kernel 或完整 M3；若需要改变选项、数据切分、指标、调用次数或门槛，先修改协议版本并说明原因，不能在看见验证结果后原地修改 v1。

## 1. 要回答的问题与边界

实验回答三个问题：

1. 同一 Decision 合同能否支持规则与真实 LLM，且错误、超时、取消、恢复不会导致越界派发或隐式重复调用？
2. 在相同输入、能力和验收条件下，LLM 能否比合理的规则基线更准确地选择能力，并改善最终任务成功率？
3. 是否保存了足够的决策与结果证据，使 M3 可以冻结开发经验并提出可评估的 Policy 候选？

本轮只实现两个选项的 `choice`，一次选择后至多执行一个 worker。所有执行代码来自受信 fixture；模型只返回结构化选择，不生成代码或工具调用。使用临时实验实例，保留普通 seed 和既有 M0–M2 行为。Rank、权限 gate、规则/模型级联、检索记忆、在线训练、动态扩图、自动晋升及 Jev Adapter 都不属于本轮。

## 2. 现有实现与必须补齐的差距

以下结论来自基准提交，不能把设计文档中的完整合同当作已实现 API：

| 位置 | 当前实现 | 本轮要求 |
| --- | --- | --- |
| `src/decision/index.ts` | choice 校验；来源只有 provider 与 policyVersion | 请求/响应运行时校验，明确错误分类，记录真实调用配置与用量 |
| `src/adapters/decision-rule/index.ts` | `rule-v1` 对 context 做键值相等匹配 | 保留既有语义；实验使用版本化词法特征和固定规则形成基线 |
| `src/app/instance.ts` | 固定注入一个 RuleDecisionProvider | 允许 app 注入按名称查找的 DecisionProvider；默认仍装配规则，实验显式装配 LLM |
| `src/runtime/index.ts` 的 runDecision | context 仅有静态图字段与 requires 布尔键；传入整段 Run 时限 | 加入经约束的任务视图，计算实际剩余时间，执行取消及调用预算检查 |
| 同上 | 只在成功后记录 choice；decision.recorded 与 node.completed 分开写入 | 全部调用状态可审计；成功选择与节点完成同事务提交，关闭崩溃窗口 |
| `src/runtime/types.ts` / `src/storage/` | Experience 保存最终结果；缺少独立决策调用账本 | 关联完整决策证据和 Experience；增加决策调用身份与额度，不能挪用 Executor Attempt |
| `src/evolution/` | M2 评估协议面向新增能力和回归 | 本轮输出独立实验报告；不把路由比较塞进 M2 eligible 评估或伪造 Candidate |

新合同归属 `decision`，调度及状态转换归属 `runtime`，持久化实现归属 `storage`，服务 SDK/HTTP 映射归属 `adapters`，依赖装配与实验入口归属 `app`。Runtime 不导入 Evolution，Kernel 不导入模型 SDK。无需为实验创建第二套生产 Runtime。

## 3. 最小场景与执行图

### 3.1 两个稳定选项

| 选项 ID | 对模型与规则公开的描述 | 受信执行实现 | 独立验收 |
| --- | --- | --- | --- |
| `local-process` | 统计输入文本的文件数、字节、行、词与 Markdown 标题 | 现有 stats-worker | stats schema、totals 一致性、完整期望 JSON |
| `capability/changed-file-summary` | 按源码、测试、文档、配置与其他类别列出变更文件 | 现有 ChangedFileSummary fixture，注册到实验快照 | summary schema 与完整期望 JSON |

每个输入包同时包含 `.txt/.md` 文件与根级 `changed-files.json`。两个能力都能读取自己的输入并产生合法结果；任务目标决定哪个结果正确。不能用“缺少另一个能力的输入”制造选择差异。沿用 `prepareWorkspace` 的复制规则，将文本目录和 JSON 文件分别作为 inputs，保证后者位于 `inputs/changed-files.json`。

所有实验任务的 `requires` 固定为 `["changed-file-summary"]`，用于保证实验能力包完整；local-process 在注册表中预装。两组选项、顺序、能力描述和声明完全相同，requires 不携带答案。使用专门实验图和策略，不复用 M2 按 requires 直接命中能力的路由规则。

```text
decision(choice) → execute(executorFrom=decision) → verify(fixed evaluator)
```

两组快照使用相同的能力、执行节点和裁判引用，只允许 decision provider 标识及 routing-policy 闭包不同。报告必须附 binding 差异以证明比较范围。`purpose=evaluation` 显式提交两个快照，不切换 activeGenome。已有 `ensureCapabilityGenome` 可用于构造临时实验组合，不能借此激活生产默认版本。

### 3.2 模型可见信息

Runtime 生成 `decision-view-v1`，包含：任务 goal、固定选项及其描述、相同格式的输入清单，以及由固定词法规则产生的公开特征。输入清单只提供相对名称、文件类型和字节数；本轮语义选择不需要原始正文。Provider 只能接收这个视图，不接收整个 Task、存储对象或工作区访问能力。

答案、期望 JSON、验收 schema 的内容与文件名、caseId/familyId、数据分组和 split、历史正确选项、验收结果均不进入视图。Task 的验收字段只交给受信 Runtime。为所有样本使用统一的输入命名习惯；输入包分配与正确选项无关。必须测试成对样本除 goal 及由它派生的词法特征外，其余视图保持一致。

输入视图总大小上限为 UTF-8 16 KiB，超限记录 `input_too_large` 并在网络调用前失败，禁止无记录截断。goal 中的命令式文本属于任务数据，不能改变固定选项、系统提示、预算或验收规则。来源记录保存实际发送视图与序列化消息的内容摘要；完整内容写入受控 blob，凭据和请求认证头永不落盘。

### 3.3 对照组与实验组

**R：规则基线。** 继续使用 RuleDecisionProvider。实验视图构造器提供 `hasStatsIntent`、`hasChangeIntent` 两个布尔特征，词表在开发集上确定并版本化。初始词表可以包含统计侧的“字数、词数、行数、字节、标题数、word count、line count”，以及分类侧的“变更、改动、文件分类、源码、配置、changed files、classify changes”。匹配规则、大小写/Unicode 归一化和优先级必须固定；只有一侧命中时选择该能力，两侧同时命中或都未命中时 abstain。允许在开发阶段修订词表，不能把规则退化成常量选择以夸大 LLM 收益。

**L：单一 LLM。** 同一公开视图交给一个真实模型，返回下面两种结构之一。整段响应必须通过严格 schema 校验，禁止从 Markdown、解释文本或近似名称中猜测/提取选项，不把模型自报 confidence 用作门槛。

```json
{"kind":"value","value":"local-process"}
```

```json
{"kind":"abstain","reason":"任务同时要求两种结果，当前只能选择一种"}
```

`value` 只能是请求中给出的 ID；abstain reason 限 512 字符，拒绝其他字段。模型服务自己的 refusal 单独保存原始类型，可映射为带明确来源的 abstain；网络错误、429、超时与非法响应不能映射为 abstain。Provider 返回的 provenance 由受信 Adapter 和请求配置填充，不相信模型自报的策略/模型版本。

实验组不自动回退规则，也不自动修复输出。abstain 使 Run 以明确原因失败并且不派发 worker；需要弃权的样本由实验裁判判为“决策处理正确”，不能把该 Run 伪装成任务 succeeded。

## 4. 版本、预算与恢复合同

### 4.1 版本来源

规则组的 routing-policy 保持 `rule-v1`，直接交给现有 RuleDecisionProvider；LLM 组使用 `llm-choice-v1`，其不可变内容包括提示模板、服务/模型标识、采样参数与响应 schema。两组共享同一 `decision-view` 槽位版本，内容为视图规则、选项描述、词表与输入限制，Runtime 负责装配并校验。复用现有 artifact/version/dependency 机制，不新增可变的 latest 引用，也不把 LLM 配置包装后误传给只认识 rule-v1 的 Provider。

迁移保留旧 rule-v1 快照和事件。没有 decision-view 槽位的旧图继续使用原静态上下文及能力键；实验图缺少该槽位则拒绝准入。旧 decision.recorded 可作为原有已记录选择恢复，但不存在的输入/用量证据必须标记 unavailable，不能补写为完整实验样本。D15 必须包含旧实例迁移与历史事件恢复。

运行记录至少包括 provider/adapter 版本、服务标识、请求的 model ID、服务报告的版本（缺省 null）、采样参数、输出上限、prompt/template digest、视图版本、响应 schema digest、策略版本和代码 commit。凭据从 app 注入；可变 endpoint 配置不能在恢复时静默映射到另一服务。模型权重无法钉住时明确 `reproducibility=recorded-inputs-only`。

首个实现只选一种与操作者现有配置匹配的服务协议，按其官方文档映射并锁定依赖。将协议名、依赖版本、配置变量和启动方法补入本目录的执行说明后再执行真实验证。不为未选定的服务虚构配置或兼容性；没有可用配置时，完成 fake 验证并将真实阶段列为未执行。

### 4.2 本轮额度

| 约束 | v1 默认值 | 执行要求 |
| --- | --- | --- |
| 每个决策节点的模型调用数 | 1 | SDK/HTTP 自动重试关闭，恢复不重置计数 |
| 每个 Run 的执行 Attempt | 最多 1 | 选择失败不派发；不靠换能力重试过关 |
| 单次模型超时 | 15 秒 | 实际超时取此值与 Run 剩余时间的较小值，底层请求支持取消 |
| Run 总时限 | 30 秒 | 剩余时间从持久化的开始/截止点计算，不能每个节点重新给足 30 秒 |
| 模型输出上限 | 256 output tokens | 包括服务计入该限制的生成部分；若服务无法支持则在预检时声明并修订协议，不能忽略 |
| 开发阶段真实调用 | 最多 100 次，最多 2 套提示配置 | 包含联通预检，记录所有调用；模型与最终提示在正式阶段前唯一固定 |
| 正式阶段真实调用 | 300 次 | 100 个样本 × 3 次重复，无补考调用 |
| 真实调用并发 | 1 | 两组使用相同任务顺序，固定种子平衡 R/L 先后顺序 |
| 单轮正式实验墙钟时间 | 最多 60 分钟 | 达限保留已有证据，整个收益结论标 inconclusive |

调用额度在同一事务内检查并预留，计入 Run 与本次 experiment 的持久化账本；进程重启不能获得新额度。Run 还必须受持久化的 Organism 决策调用总额度约束，不能通过换 experimentId 绕过限制；规则本地计算不消耗远端调用额度。明确记录已经发送的调用数、input/output tokens、已知费用、币种与价格依据引用，缺失字段为 null。令牌和次数上限不等于精确货币硬上限；要求费用硬上限的环境须由服务/宿主提供可验证限制，否则预检失败。此次正式比较不宣称成本下降，未知成本不会记为免费。

实验额度只能支持本轮运行，不算完成 M3 的独立评估预算池。既有 Organism/Run 限制继续生效；需在临时实例的运行清单中显式配置足够余额，禁止为通过测试绕过生产预算校验。

### 4.3 决策调用状态与崩溃窗口

每次决策生成持久化 `decisionId`，关联 experiment、run、node 与输入 blob。其调用记录独立于 Executor Attempt，至少区分 prepared、started、value、abstain、invalid_output、transport_error、timeout、cancelled、unknown。prepared 和 started 只是内部生命周期，不作为模型回答。

| 崩溃/失败位置 | 恢复与执行要求 |
| --- | --- |
| 尚未提交调用准备记录 | 没有网络调用，可正常开始 |
| prepared 已提交但未进入 started | 使用原 decisionId 与预留额度；确认未发送后允许首次发送 |
| started 已提交至响应终态保存之前 | 可能已发生调用/计费；保留 unknown，不自动重发、不派发 worker |
| 合法 value 已保存 | value、decision.recorded 和 decision 节点成功同事务；恢复直接使用记录，不再次推断 |
| 已有失败/abstain 终态 | 恢复沿用失败原因；节点和 Run 状态补齐，不重调模型 |
| timeout / cancel 后迟到返回 | 关联原 decisionId，追加迟到证据；不改原终态、不派发 worker |
| 请求 blob/策略版本丢失或摘要不匹配 | 明确不可恢复，不能用当前源文件或新模型补齐 |

started 记录必须先于真正网络发送；因此可能将“标记后、发送前崩溃”保守判 unknown，这是为避免重复计费接受的可用性代价。能否查询服务结果另行声明；v1 没有查询能力时保持 waiting，并提供显式取消结案入口，保留 unknown 证据与未结算费用。取消已结束的本地执行不证明远端费用为零。

请求前、响应接受时和 worker 派发前都检查取消与实际剩余额度/时间。网络调用在数据库事务外执行，结果和节点投影在一个短事务提交；不能跨 `await` 持有 SQLite 事务。普通 recover/execute 入口也必须尊重未解决的决策调用，不能只在实验 runner 内阻止重发。

### 4.4 经验最小字段

保存 requestRef/digest、decisionId、runId、nodeId、snapshotId、全部策略来源、开始/结束时间、选项、规范化结果、错误分类、原始响应引用、用量与费用、是否迟到；最后通过 runId 关联执行 Attempt、固定裁判、实际输出 digest 和 Experience。失败决策同样保留，不能只导出成功样本。等待中的 unknown 尚无最终 Experience 时保留开放记录，不虚构结果。

gold label、schema 与预期输出存于独立评估资料中，由 case→run 映射连接，不能回写模型输入。本轮不采集隐藏思维链；只保存服务实际返回且允许记录的响应和必要诊断。

## 5. 数据集与防泄漏规则

全部数据使用合成 fixture。每个 case 都有独立 caseId、familyId、stratum（下表的数据分组）、goal、input bundle digest、expectedChoice（选项 ID 或 abstain）、schema/期望输出引用。实验 arm 专指 R/L，不能与 stratum 混用。相关目标的改写、相同模板、同一输入包的衍生样本必须归入同一 family，并整体进入同一个 split；不能以改几个文件名或数值充当新的独立问题。

| 分组 | 目标 | 开发集 | 正式验证集 |
| --- | --- | --- | --- |
| explicit | 明确要求文本统计或变更分类，中英均覆盖 | 8 | 20 |
| paraphrase | 同义表达，不只重复基线词表 | 8 | 20 |
| distractor | 目标明确，但出现另一个能力的背景词或否定描述 | 8 | 20 |
| contrast | 只改变目标就应改变选择，输入包相同；成对任务 | 8（4 对） | 20（10 对） |
| abstain | 信息不足与同时要求两种结果各占一半 | 8 | 20 |
| 合计 | 可执行选择与应弃权分别评分 | 40 | 100 |

前四组内两个正确选项各占一半；正式集固定 80 个可执行任务、20 个应弃权任务。非 contrast 组每项来自不同 family；contrast 同一对共享 family。开发与正式集的 family 完全不重叠。每组至少覆盖两种语言表达；输出内容和输入目录名不得与组别或正确选项绑定。

表格只规定覆盖和数量，不能根据 LLM 或规则在验证集的错误反向选择困难样本。数据作者按任务语义标注正确选择；可信 evaluator 用固定期望 JSON 验证输出。期望结果依据能力规范独立计算并复核，禁止只把受测 worker 的一次输出直接当标准答案。

开发集可用于规则词表、提示和 bug 修复。正式集由验证负责人在开发配置冻结后提供；开发 agent 不读取其目标与答案、不把它用于提示示例。若独立人员/权限隔离不可用，必须披露开发方可见范围，只能报告 fixture 上的探索结果，不能宣称独立 held-out 证据通过。

首次正式模型调用前，冻结 manifest：协议版本、完整 split 成员、所有输入/答案/schema 的摘要、规则与提示、两个快照、模型参数、运行种子、资源上限和报告算法。记录冻结时间与代码 commit。正式集的标签由 evaluator 单独加载，不传给模型；运行目录只放需要执行的输入，标准答案不挂载给 worker。

正式结果公开后，这套验证集只可作为后续回归集，不能继续充当未见验证集。M3 必须另备新的验证 family；本实验验证集的失败不能在同一轮同时当学习材料和晋升证据。

## 6. 执行顺序

1. **工程预检**：完成第 9 节全部合同与回归测试；使用 fake 的运行不产生模型收益结论。
2. **开发调试**：只用 40 个开发样本完成规则、提示与输入视图；保留每套配置及调用记录。冻结唯一规则与唯一 LLM 配置。
3. **验证资料冻结**：独立准备正式 100 个样本，检查 family/内容重复、标签隔离和 binding 差异，生成完整 manifest。不能在冻结后补填门槛。
4. **Oracle 能力预检**：对正式集中 80 个可执行任务分别强制选择正确能力和另一个能力；正确选择必须验收通过，错误选择必须被同一固定裁判拒绝，共 160 个预检 Run。通过测试专用 Provider 强制选择，不在生产接口新增绕过选择校验的通道。Oracle 只检查执行/裁判装配，不计入路由收益，也不调用模型。任一预期不符先停止，修复后重新冻结新的实验记录，保留失败记录。
5. **正式比较**：全部 100 个样本在 R、L 两组各运行 3 次，共 600 个全新 Run，其中 L 最多 300 次真实调用。按 manifest 固定的顺序和种子平衡组别先后；每次调用使用独立上下文，无对话延续和跨样本结果缓存。规则重复运行用于验证确定性与执行稳定性。
6. **故障处理**：429、服务错误、非法输出、取消和超时都保留在原计划分母内，记作该次未成功；不补考。全局时限/额度到达或不可恢复中断造成样本缺失时，保留部分报告并给出 inconclusive。记录已知完成的 case/arm/repeat，恢复只执行尚未开始的单元，不能覆盖旧结果。
7. **汇总与收口**：离线从 manifest、数据库和逐次记录生成报告；汇总过程不调用模型。提交工程改动、合成 fixture、可复算报告与执行说明，真实调用敏感原文保留在授权实例，不随仓库提交。

## 7. 指标、门槛与结论

### 7.1 指标的精确定义

可执行样本数 N=80，重复次数 K=3。`s[g,i,r]` 在且仅在选择 gold 能力、执行完成、固定裁判与完整期望 JSON 均通过时为 1，其余为 0。组别 g 为 R 或 L。

- **端到端成功率 Sg**：`sum(s[g,i,r]) / 240`，主指标。开发结果、Oracle 和应弃权样本不进入分母。
- **收益 Δ**：`SL − SR`，使用百分点；同时报告每轮 80 个样本的成功率和收益，不仅给平均值。
- **选择正确率**：可执行样本中返回 gold ID 的比例；选择正确但执行/验收失败仍不算端到端成功。
- **应弃权正确率**：20×3 次应弃权任务中明确 abstain 且零 worker 派发的比例。异常/超时不算正确弃权。
- **错误派发率**：应弃权任务仍选择任意能力并派发的比例；越选项/未安装能力的派发另列为工程违规，不能被平均分掩盖。
- **coverage 与失败分布**：全部 300 次决策中合法 value 的比例；abstain、invalid_output、transport_error、timeout、cancelled、unknown 分别计数。
- **时延**：记录全部调用的实际耗时、成功调用的 p50/p95 和 Run 总时长；timeout 不从全调用时延删除。p95 采用排序后 `ceil(0.95*n)` 位置值。
- **成本**：分别列真实请求数、已报告 tokens、已知金额与未知条目数；不能把未知金额代入平均费用或宣称相对节省。
- **重复稳定性**：每个 case 的三次结果向量，以及一致选择的 case 比例；三次调用不视为三个独立任务。

报告必须按五个 stratum 分列，并列出配对的改善/退化/不变 case 及 family。contrast 的 10 对须单列“两个任务均正确”的比例。实验为固定合成任务上的探索性比较，不以 300 次调用宣称 300 个独立样本，也不作一般任务上的统计优越性结论。

### 7.2 工程门

第 9 节全部场景通过；M0–M2 回归通过；存在真实调用时每次都有完整来源和调用状态；重放/恢复没有隐式模型重调或重复 worker 派发；预算和取消门不可绕过；普通实例 activeGenome 与原 revision 不被实验修改。

fake 通过仅得到 `engineering=passed`。真实配置缺失则 `realModel=not_run`、`benefit=inconclusive`，整体交付注明待验证。缺少原始证据、发生样本泄漏或比较快照超出允许差异时，不能报告独立收益通过。

### 7.3 收益门

真实数据完整、Oracle 全过、正式集独立且工程门通过后，LLM 必须同时满足以下预设条件，才可写 `benefit=demonstrated_on_fixture`：

| 条件 | v1 门槛 |
| --- | --- |
| 整体任务成功 | L 三轮各至少 72/80 成功（90%） |
| 相对改善 | L 相对 R 三轮各至少净增 8/80 成功（10 个百分点） |
| 分组下限 | 前四组在 L 每轮各至少 16/20 成功（80%） |
| 明确任务回归 | explicit 中 R 三次全成功的 case，L 也须三次全成功 |
| 弃权能力 | L 每轮至少 18/20 正确弃权（90%） |
| 有效响应 | L 正式集 invalid_output=0；不能靠猜测、回退或隐式重试达标 |
| 使用时延 | L 成功决策 p95 ≤ 5 秒；所有调用受 15 秒硬超时约束 |

这些门槛是决定是否值得继续该路由方案的产品取舍。规则已经接近满分时，实验可以没有足够改善空间；不能削弱基线追求通过。数据完整但收益条件未全部满足，记 `benefit=not_demonstrated`；环境预检失败、缺少正式数据或独立性不足，记 `inconclusive`。任何收益结论均不产生 Promotion，也不等价于“系统已经会学习”。

## 8. 报告与可复算交付物

实现一个由 manifest 驱动的实验入口，以及只读证据生成报告的入口。现有项目尚无这些命令，开发 agent 必须在实际实现后补充精确命令、参数、退出码和可复制示例；本文不把拟议名称写成已经可运行的 CLI。

每轮运行的输出至少包括：

| 文件 | 必需内容 |
| --- | --- |
| `manifest.json` | 协议 ID/摘要、基准与实现 commit、开发冻结时间、数据/split/答案/裁判摘要、两组快照差异、规则/提示/模型版本、随机种子、额度 |
| `trials.jsonl` | 每个 case/arm/repeat 的 stratum、decisionId/runId、状态、选择、期望选择的独立引用、验收、输出摘要、耗时、用量、错误和证据引用 |
| `report.json` | 分母、逐组逐轮指标、所有门槛与实际值、工程/真实验证/收益三个结论、未执行与未知项 |
| `report.md` | 主要结论、改善与退化样本、故障/数据独立性说明、可复算命令、M3 可用经验范围与局限 |

把缺失/损坏 blob、重复 trial key、输入摘要漂移、未开始的 trial、unknown 调用都显式列出。聚合须校验唯一键 `(experimentId, arm, caseId, repeat)`，报告不能悄悄丢弃失败行。Oracle 和开发结果另存并标记用途，不混入 600 行正式比较记录。合成且无敏感内容的冻结 manifest 和报告可进入仓库；实例数据库/凭据/远端原始认证信息不提交。

CLI 要能区分“工程/预检失败”和“实验完成但收益未证明”。收益不足不等于测试框架失败；预算中止或无凭据也不能以空报告显示成功。具体退出码由实现定义并在使用说明中固定。

## 9. 必须实现的验证场景

| ID | 场景 | 可观察验收 |
| --- | --- | --- |
| D01 | Rule 与 fake/真实 LLM 返回合法 ID | 相同合同独立校验，选择实际控制 executorFrom，恰好一个 worker |
| D02 | goal 在两种任务间切换，输入与 requires 不变 | fake 指定不同合法响应时，两条真实执行路径分别通过自己的固定期望结果 |
| D03 | 有效 JSON 但未知 ID、错误类型、额外字段；Markdown 包裹 JSON | invalid_output，零 worker 派发，保留响应与错误证据 |
| D04 | 明确 abstain、服务 refusal、429 和断网 | 弃权与传输错误分别记录；无默认选择、无自动重试 |
| D05 | deadline 已过、调用超时、取消与迟到响应 | 超时/取消可结束本地等待；迟到结果不启动 worker；测试包括永不 resolve 的 fake |
| D06 | 两个并发 Run 竞争最后一个实验调用额度；跨实验争用 Organism 额度 | 仅一个进入网络调用；另一方预算失败；Run 重启与新 experimentId 不重置额度 |
| D07 | prepared/started/响应提交等边界崩溃 | 符合第 4.3 节；特别覆盖 choice 已存但节点完成未存的旧窗口 |
| D08 | 决策成功后崩溃，再 recover/replay | 使用原 choice 与快照，模型调用计数不增加，worker 不重复执行 |
| D09 | 提示/模型配置在新快照变化，旧 Run 恢复 | 原请求版本不漂移；缺少其配置/内容时明确失败 |
| D10 | schema/答案路径与内容、caseId 具有泄漏标记 | fake 捕获实际模型请求，断言这些标记完全不可见；超限输入在发请求前被拒绝 |
| D11 | 修改裁判、输入文件或 manifest 摘要；删除 blob | 预检/复算失败并指出漂移；不以候选自报结论通过 |
| D12 | 账单字段缺失、timeout 后服务可能仍计费 | unknown/null 被保留；不释放未知费用为零，不宣称硬费用封顶 |
| D13 | 无效 choice 指向未授权/未安装执行器 | Runtime 校验与既有授权/装配约束生效，零副作用；决策不能更改 options |
| D14 | 固定 trial 表含错误、重复行、缺失行、退化样本 | 汇总分母正确，重复/缺失不静默跳过，能得到 not_demonstrated/inconclusive |
| D15 | 所有现有测试、旧实例迁移与历史 decision.recorded 恢复 | M0–M2 保持兼容，无模型凭据也能通过日常 CI；旧证据缺项明确 unavailable |

测试按现有 unit / contract / integration / acceptance / evals 布局安排。fake 必须能模拟传输失败、延迟取消、started 后断连和重复返回，不只返回立即成功。真实模型接口兼容性单独显式启用，不能由 fake 代替。

一个实现 agent 可依序完成 E1–E4；E5 交给未参与调参的验证负责人。多个实现 agent 并行时先固定 E1 合同，再明确各自文件范围；Runtime/Storage 的事务变更由同一个负责人集成，避免多方各自实现不一致的状态机。此表规定交接责任，不要求现在创建任务或自动启动其他 agent。

E3 的全数量 fake 演练使用专门的管道测试数据，可以由开发 fixture 派生；它不创建或提前读取 E5 的正式验证集。报告标记 `datasetPurpose=plumbing-test`，不能与独立验证结果混合。

每个切片先核对基准以来的变化，阅读 ADR 0007、本文及 `runtime.md`/`repository.md`，然后实现对应验收。提交说明写清行为变化与证据，最终执行现有 `pnpm check`。文档编写阶段无需运行模型或全量代码测试；实现阶段必须运行相关检查，真实模型执行依赖显式配置与本轮额度。

完工清单：代码与迁移、合同/恢复/报告测试、开发 fixture、真实服务配置说明、冻结 manifest、逐次证据、可复算报告、独立验证集的使用与泄漏声明。未完成的真实步骤必须列明缺少的具体条件；不能把工程通过写成整个实验已完成。

## 11. 交接到 M3 的条件

E1–E5 的记录与结论用于编写 ADR 0008；收益未证明时仍可整理证据，选择继续规则策略或修订下一版实验，不要求强行采用 LLM。

M3 的首个候选建议只改变路由 Policy，保持执行能力和裁判固定。ADR 0008 至少明确：冻结经验的成员与内容摘要、开发数据和新的独立验证 family、可修改的策略字段、Consolidation 的候选数/预算/停止条件、收益与回归门槛，以及 Candidate→Evaluation→operator Promotion 的关系。本实验的 model/prompt 版本与未知结果处理语义可以复用；规则归纳、检索或微调算法尚未由本文决定。

M3 实施前须兑现真隔离、裁判独立晋升、独立评估预算三个前置。冻结只包含有权限读取的确切经验成员，保留失败与 unknown；本轮用于调参的开发经验可作为学习来源，已经暴露的验证资料只能作回归用途。每个候选关联来源 dataset digest，新的验证证据不足时不晋升；采用后新 Run 使用新策略，旧 Run/恢复仍使用旧快照。

M3 的隔离与预算准备可以与本实验并行规划；经验驱动规则改进不依赖 LLM 或 Jev 必须胜出。真实隔离未就位时，本实验受信 fixture 的结果不能被用作生成代码在宿主机自主执行的授权。

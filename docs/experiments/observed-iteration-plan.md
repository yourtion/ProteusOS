# O2：真实观测后的迭代与验证计划

2026-10-28。依据 [O1 完整结果](./results/adaptive-observed-v3.md)及本次[离线诊断](./results/adaptive-observed-v3-diagnosis.json)。当前状态是 **O2-00 / O2-01 已提交，O2-02 与 O2-R1 均结案**。用户已要求提高上限并按顺序迭代验证；输出 256/512 对照沿下述新协议执行，未修改 O1 清单。

## 当前判断

| 证据 | 可以得出的判断 | 还需要验证 |
| --- | --- | --- |
| 830 Run、450 测量单元全部到齐；归档复算一致 | 调度、原始收据与离线复算可工作 | 历史一次未知用量使计量仍为 incomplete |
| 单次 formal 69/120；三次 72/120；两者 regression 均 19/30 | 三倍调用仅多 3 个 formal 成功，当前缺少增加调用的价值依据 | 跨新任务和重复实验的稳定收益 |
| formal 配对：双方成功 57、仅单次成功 12、仅三次成功 15、双方失败 36 | 三次执行既有救回也有退化，不能只报告救回的 15 个 | 修复基础输出后是否仍需多次执行 |
| 示例 formal 2/120、regression 2/30；49 次弃权均自述缺少当前任务 | 当前示例组合不可采用；当前任务在示例后的呈现方式是优先假设 | 改变消息布局能否消除该现象，不能用自述证明正文确实缺失 |
| 349 次 invalid_output 全部输出用量为 256：317 空正文、32 非空非法 JSON | 输出额度与无效输出高度相关，必须与布局一起纳入开发诊断 | 具体服务结束原因及因果；另有 3 次 value、1 次 abstain 同样用到 256，不能以用量判定截断 |
| formal 的 10 个 family 中，示例仅 2 个 family 出现成功；基线有 1 个 family 全部失败 | 总平均掩盖了任务差异，需要按 family 和目标能力分层 | “文档讨论 changed files，但要求统计文档文本”的歧义任务能否稳定通过 |

优先修复“有效表达当前任务并得到完整合法响应”的接口。原始记录中没有误派不等于系统可靠：大量失败发生在作出有效选择之前。不能把这些失败换算为良好的路由准确率。

O2-00 与 O2-01 均先用本地合同/恢复测试验证，不需要真实生成。结束证据只保存受信服务元数据，不记录凭据或隐藏推理正文；`stop_reason` 必须取自真实响应，不能由 token 数或字符串形状推断。

第一版新布局保持原 system 正文，只把末条泛化请求改成“当前 decision-view + 决策 JSON 指令”，零/双示例都用同一格式。这样可以明确测量把当前任务放到最后 user 的效果。迁移掉 system 内的重复任务、改系统指令或更换模型若有必要，另做后续版本，不混入此次因素。实际输入 token 增加须计入成本并通过同正文预检。

新策略的 request format 属于固定组件；优化器仍只选择/重排示例，不能借搜索改变格式、模型或额度。旧 v1 解析与渲染保留原分支，缺省旧产物不能自动升级或补入新字段。参数比较、预备请求恢复和实验审计都必须识别新旧格式。

定向验证复用并扩展以下文件：

- `tests/unit/llm-demos-policy.test.ts`：新旧策略、固定字段与参数白名单。
- `tests/contract/llm-demos-adapter.test.ts`：结束证据、零/双示例、最后一条当前视图、计数与发送正文一致、用量缺失。
- `tests/integration/llm-demos-runtime.test.ts`：prepared 旧请求回放、正文漂移拒绝、unknown 不重发、原始证据清理后复算。
- `tests/integration/observed-experiment.test.ts`：旧 v1/v2/v3 报告兼容；新开发入口另加真实规格的 fixture 全流程与额度/截止反例。

每个代码切片完成定向验证，再执行 lint、format、typecheck 和全量回归，随后提交。仅真实测量和报告归档阶段使用独立回放与摘要核对，无代码变化时不重复全套测试。

## O2-02：160 次开发诊断矩阵

沿用同一服务/模型、temperature、响应 schema、固定两条 train 示例、受约束 worker 和裁判。新增 10 个开发任务、10 个模板 family，两个目标能力各 5 个；包括含干扰关键词的目标判别。明确开发可见，不声称独立保管，也不把 O1 已见 formal/regression 重新命名成未见验证。

因素只取以下组合，共 8 个条件：

| 因素 | 水平 |
| --- | --- |
| 请求布局 | v1；v2 当前任务置于最后 user |
| 输出额度 | 256；512 |
| 示例数 | 0；固定 2 条 |

`10 任务 × 8 条件 × 2 repeats = 160 次生成`。各任务条件顺序按冻结 seed 轮转，全部参数、任务正文、家族关系、期望 JSON 与选择规则在首次请求前固定。输入仍按同一正文计数预检 ≤2,048，并与实际用量核对；不把该预检升级为输入硬上界证明。

前 16 次选两个目标能力各一个任务、覆盖 8 条件一次，属于 160 次中的已登记槽位。核验 512 参数兼容、结束证据与计量；若这 16 次完全没有合法 value，按预登记条件停止并记录未执行分母。以后不得以新目录重新发送这些槽位。格式错误和模型弃权作为观测继续计分；用量未知、计数漂移、超额或身份不匹配则立即停止。

按相同额度/示例数比较布局，按相同布局/示例数比较额度，报告交互、逐 family 成功、有效 value、模型弃权、服务 refusal、非法输出、结束原因、延迟及全部用量。不能把 8 条件中最好的结果直接解释为独立收益。

进入确认的开发条件：完整计量；合法决策 JSON ≥95%；实际任务成功 ≥90%；misroute ≤5%。每条件 20 个单元，至少对应 19 个合法 JSON 和 18 个实际成功。若无配置满足，停止，不启动 750 次测量。需要更大额度时另登记新矩阵，不能看完结果再向本矩阵补加 1,024。

筛选至多一个配置：先按 family 等权实际成功率，依次以较小输出额度、较少示例、较少已知总 token、固定条件顺序打破同分。无示例胜出时如实保留该基线，不伪造编译候选。

## O2-03：120 次开发确认

在矩阵结果选定配置之后，冻结另外 20 个开发确认任务（10 个 family，每 family 2 个变体）、其中 4 个预先标记关键任务。确认集不用于继续搜索或调整提示，开发方可见的性质不改变。

`20 任务 × 2 配置 × 3 repeats = 120 次生成`。有示例候选对照相同布局、相同额度的无示例配置；v2 无示例候选对照相同额度的 v1 无示例；v1/512 无示例候选对照 v1/256 无示例，直接确认提高上限的改进。若 v1/256 无示例胜出，则没有不同的改进配置，停止而不重复相同策略。

两配置均须完整计量；候选合法 JSON ≥95%、成功 ≥90%、关键任务全部通过；相对固定对照成功率至少提高 5 个百分点。各臂 60 个单元，5 个百分点为 3 个净成功，结果仍只是进入下一阶段的开发筛选信号，不宣称统计或独立收益成立。

- 示例配置通过：允许准备 O2-04 的新三臂清单。
- 仅无示例布局改进通过：记录基础接口改善，停止示例扩展；若后续搜索新示例，须另登记和计费。
- 无改进或关键回归失败：保存失败与成本，停止扩大实验；继续定位已明确的失败类型。

## 预算、截止与效果资格

本计划尚未派发新增调用。推荐的新改进链预算为：开发矩阵最多 **160**、确认最多 **120**，合计 **280**；若通过后再做三臂测量 **750**，新链共 **1,030 次**。这不含 O1 已发生的 **793 次**历史准备/观测，累计应列为 **1,823 次**；计数 API 请求另列。兼容检查包含在矩阵内，裁判与来源使用本地受约束执行，不添加模型裁判、teacher 或隐式重试。

**1,030 是后续新协议的预算草案，不是修改 O1 的 800 次上限。** 后续派发前必须把分阶段及全链累计额度写入新登记；若仍要求单条改进链 ≤800，必须先缩减开发设计或延期全规模测量，不能省略 280 次开发成本。O1 的历史未知调用持续保留。

每次 Run 仍按 30 秒总上限，发送前计数、SDK 28 秒后备和无自动重试保持一致。新阶段总时限按冻结 Run 槽位数 ×30 秒加 300 秒收尾预算确定；派发前若不足一个完整 Run 的时间则停止领取，保留未开始槽位，不为赶总截止主动截短已经声明的每次时间窗口。该时限是最坏情况保护，不是运行时间承诺；外部超时仍可能产生未知，出现后不重发。完整测量时限与分段规则必须在新轮开始前固定，避免再因原先 60 分钟估计不足临时延长。

O2-04 采用新任务、冻结三臂和完整分母，报告先前开发成本及原始收据；采用门保持显式。模型输入硬上界、独立保管、真实 family 数及正式 Evaluation 桥接不足时，仍只能出具 `inconclusive` 的观测结果。当前建议从 **O2-00 → O2-01** 两个零生成调用的工程切片开始，验证后分次提交。

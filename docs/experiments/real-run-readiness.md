## 尚缺的正式条件

1. **模型输入硬上界。** 兼容端点支持 `count_tokens`，当前一次计数与实际输入一致；这不证明服务每次都以同一计数生成，也不提供输入超限拒绝的合同。智谱[核心参数](https://docs.bigmodel.cn/cn/guide/start/concept-param)明确 `max_tokens` 仅限制输出、不包含输入；[兼容说明](https://docs.bigmodel.cn/cn/guide/develop/claude/introduction)也提示兼容差异。当前没有可核验的输入限额服务/网关或与实际模型模板绑定的 tokenizer。因此不把一次实测匹配、字符估算、任意安全系数或用户自报上限当作预算证明。
2. **来源模式证明。** 本地确定性来源需要原始约束和实际路由来源绑定；编译后端自报 `mode=real` 不足以升级既有 fixture。需要在模型/执行预算合同装配后完成来源核验与真实准入。
3. **正式资料保管。** 原协议的独立收益需要至少 20 train / 20 search / 40 formal / 10 regression family，衍生任务归同一 family。资料生成者不能自证“独立保管”。开发方可见资料可以做真实观测，但结果须保留 `inconclusive`。
4. **正式 Evaluation 桥接。** 新入口须原子绑定候选/清单、一次领用和失败封存。当前已实现的 fixture Journal 不领用正式集，也不产生可晋升的 Evaluation。

## 路径 A：继续原协议

取得输入硬上界来源（服务拒绝合同，或可固定的模型 tokenizer/消息模板与最大输入约束）及独立资料后，依次完成真实来源证明、逐派发限额、正式集一次领用和新版 Evaluation，再运行完整正式轮。

固定 50 个 formal/regression family × 3 repeats × (1+3+1) = **750 次**正式/回归模型调用。本地确定性开发来源不消耗模型调用，最低两组参数 × 20 search = **40 次**搜索，合计 **790 次**。任何额外 teacher、重试、模型裁判或执行器内请求均须纳入，不得为满足 800 次上限漏记。无合格候选时记录开发负结果，不能为强行进入正式轮降低原选型门槛。

## 路径 B：单独注册真实观测协议（已选择）

如果当前目标是先获取完整三臂真实测量，可另注册 `adaptive-observed-v1`，不修改 `adaptive-behavior-v1` 的拒绝门：

- 仍使用上述完整样本规模、三次重复、1/3/1 对照、无 gold 选择器和串行轮转；正式前固定所有数据/配置/搜索计划及总额度。
- 每次发送前用服务计数检查同一冻结正文 ≤2,048，输出参数 ≤256；宿主持久化最多 800 次生成、60 分钟截止与已占预留，unknown 不重发。输入计数核验是**观测性预检**，不是已证明的输入硬限额；每次响应核对实际用量，缺失/漂移/超额即停止。
- 资料为开发方可见时如实记录。单一模板的多个改写不得凭新 ID 计作独立 family。
- 报告三臂实际质量、回归、延迟、全部已知/未知成本，独立收益始终 `inconclusive`，不产生可晋升的正式 Evaluation 或 Promotion。
- 编译仍无合格候选时保留负结果并停止；如果要比较预先指定的示例策略，须在调用前另行明确其为固定策略消融，而非编译器成功。

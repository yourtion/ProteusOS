## 3. 自举验收故事

ChangedFileSummary 的验收流程由 `tests/acceptance/bootstrap-story.test.ts` 固化：

1. 缺少能力的任务创建固定快照的等待 Run；到期或显式接替后结案。
2. 在独立工作区委托构建，固定测试通过后记录产出摘要。
3. 采集不可变能力版本，构造候选并固定输入、裁判、预算与回归计划。
4. 独立评估新能力及既有能力回归；健康基线失败记 inconclusive。
5. 操作者批准 CAS 晋升；冲突候选返回 stale，须重建与重评。
6. 显式 supersede 创建使用新快照的接替 Run，完成原任务。
7. 回滚到历史采用快照，revision 继续增长；保留已发生的结果和证据。

裁判变化先作为独立候选评估与晋升，再评估能力候选。

## 4. 持续验收的失败场景

| 场景 | 预期行为 |
| --- | --- |
| 候选失败、输出非法或依赖缺失 | 保留证据，禁止晋升 |
| 同 revision 并发晋升 | 一个成功，另一个 stale |
| 提交成功但响应丢失 | operationId 读回原结果，不重复增加 revision |
| 外部调用结果未知 | 保留 unknown，不假定未执行并自动重发 |
| 在途 Run 遇到默认版本变化 | 原 Run 和恢复仍用原快照 |
| 权限撤销 | 阻止新调用和派发；已发生的结果不被抹去 |
| 未发送调用取消或撤权 | 提交取消终态，释放未发送额度 |
| 迟到响应 | 追加证据，不覆盖已确认终态或派发 worker |
| 更换裁判或固定验证内容漂移 | 拒绝自我放行与借用旧证据 |
| 冻结成员/输入 blob 缺失 | 明确不可回放，不填充替代内容 |
| 共享内容带私有依赖 | 发布/导入拒绝 |
| 来源公钥撤信或 registry 凭据撤销 | 拒绝相关新动作，保留历史证明与本地采用记录 |

实现边界见 [运行时合同](./runtime.md) 与 [进化流程](./evolution.md)，标准检查见 [仓库设计](./repository.md)。

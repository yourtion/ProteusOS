# 设计原则

ProteusOS 关注一个具体问题：系统能否因为经历过先前任务，在后续任务上变得更可靠、更有效，同时保留用户控制和行为的可解释来源？

它的长期目标是持续适应；首版工程目标是证明一个完整闭环：执行产生证据，证据支持候选，候选经比较后被采用，后续运行使用新行为，并能够回到旧行为。

## 从第一性原理到约束

| 需求 | 工程约束 | 可观察的验证方式 |
| --- | --- | --- |
| 系统需要跨任务积累 | 身份、经验和行为版本独立于临时进程 | 执行器退出或切换后，个体身份与历史仍连续 |
| 经验可能错误或偶然 | 观测、结论与候选分开，保留来源和适用环境 | 单次成功不会直接覆盖默认策略 |
| 变化必须有保留机制 | 产物版本不可变，谱系和晋升记录可追踪 | 能回答一次行为用了什么、为什么启用 |
| 改善不能仅靠自我描述 | 固定基线与验收标准，比较候选和旧版本 | 执行器声称完成但测试失败时不能晋升 |
| 资源和权限有限 | 执行前检查授权，执行中记账、限制与取消 | 学习任务不能耗尽在线任务预算或扩大权限 |
| 不同状态变化风险不同 | 多时间尺度可塑性，变化规则与内容分离 | 临时计划可改，稳定规则不能被候选自行改写 |
| 个体有不同目标 | 独立经验归属与默认行为，继承须本地选择 | 团队产物发布不改变个人在途运行 |

## 七条原则的具体含义

1. **约束先于优化。** Viability 在本项目中指预算、完整性、权限和可靠性约束。它服务于用户目标，不产生系统独立的自我保存目标；停止、撤权和删除请求始终属于操作者控制。
2. **预测应当能够被检验。** 对有价值的动作记录预期结果、实际观测和偏差。没有预测就明确记为未知，不生成虚假的概率或精确误差。
3. **经验先于抽象。** 先保存足以追溯的经历，再提出可复用结构。人工编写的 seed skill 可以直接作为初始版本；一次经历也能产生候选，但不能仅因产生过就获得通用有效性的认定。
4. **生成、选择、授权分离。** Planner 或外部 Agent 提供方案，Decision 进行结构化选择，基质验证权限；模型不能通过选择“允许”来授予权限。
5. **变化有不同时间尺度。** 任务内的计划调整、跨任务的策略更新、学习机制更新和基质升级采用不同流程。快变化也需记录来源与适用范围。
6. **进化包含变异、选择和保留。** 生成代码、重试成功、摘要记忆分别只是步骤。可继承改进必须经过候选、评估和晋升。
7. **自我模型基于证据。** 能力、版本、预算、失败模式可以从记录中构造；模型对自身的描述是可校验的主张，不能代替真实能力和授权状态。

## 神经科学启发的使用边界

讨论中的互补学习、经验回放、全局工作空间、预测误差和元可塑性在这里是工程启发。本设计不宣称模拟完整人脑，不将某个脑区与某个软件模块一一等同，也不以生物类比证明算法有效或系统具有意识。

| 启发 | 本项目采用的设计 | 延后验证的假设 |
| --- | --- | --- |
| 快速经历记录与慢速结构学习 | 在线收集与离线巩固分离 | 哪种巩固方法带来跨任务收益 |
| 回放与巩固 | 可重建记录、离线重评、隔离重执行 | 历史样本如何采样才减少偏差 |
| 有限工作空间 | 上下文按权限与预算筛选 | 何种选择策略优于固定检索 |
| 预测与误差 | expected/observed 的可选结构化记录 | 是否需要学习式 world model |
| 多尺度可塑性 | L0–L4 变化规则 | 各尺度的最佳更新频率 |
| 元可塑性 | 学习规则也可成为受严格评估的候选 | 修改学习机制能否稳定改善长期表现 |

“睡眠”表示后台学习阶段，不要求进程休眠或所有任务停止；“一代”表示固定的经验与版本比较条件，不要求全局同步屏障。具体约束见[进化设计](./evolution.md)。

## 什么属于最小系统

Seed 必须包含可执行的初始规则、基础执行能力和独立验收机制。系统不会从没有先验、工具和评价标准的空白中自举。

首版采用固定图与规则决策，也能验证身份连续性、执行记录、候选评估和行为替换。LLM、Jev 类决策模型、本地分类器、reranker、微调模型和外部编码 Agent 都是可替换实现。是否引入它们应由任务需求与测量结果决定。

Memory、Skill、Policy、Model 共享版本、证据和变化治理机制，但不强迫它们使用同一种内容格式、检索方式或学习算法。统一的是变化流程，不是所有模块的实现。

## 成功与失败的判据

成功不以“自主调用了多少次模型”或“生成了多少技能”衡量，而以固定任务集上的结果、回归率、成本、时延和人工纠正量比较。质量、成本和权限约束分别展示，不能通过增加一个总分掩盖硬约束失败。

如果候选只能在自己的训练经历上更好、不能复现、需要扩大权限才通过，或者无法解释行为变化来源，就还没有形成可信的改进。首版不承诺统计因果归因，只确保未来可以做这样的分析。

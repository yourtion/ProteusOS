# 本体决策最小实验：有限选择、独立评估与经验记录

M2 已证明能力可以被构建、评估和采用，但在线选择仍由 `RuleDecisionProvider` 完成。接入模型前，需要验证任务信息能否支持更好的选择，以及决策记录能否成为 M3 的学习材料。因此在 M2 与 M3 之间安排一个有限选项的本体决策实验；架构方向沿用既有设计，本文中的实验默认值尚待实施验证。

这里的“本体决策”指 Organism 的 Run 经 `DecisionProvider` 选择下一项允许的行为。Runtime 装配上下文并验证结果，Executor 执行选中的能力，Kernel 保持身份、授权、版本和晋升不变量。接入 LLM 不赋予 Provider 执行命令、修改图、修改裁判或晋升的权限。

**首个实验只做 `choice`。** 在文档统计与变更文件分类两个已安装能力之间，根据任务目标选择执行器。规则与 LLM 看到相同的公开任务信息，使用相同能力、输入和固定裁判；对照只改变决策实现及其版本化策略。先验证语义选择与最终任务成功，暂不扩展动态 planner、模型级联、rank/gate 或自动学习。这样能把决策效果与执行器能力差异分开测量。

**一次决策也是需要恢复和预算约束的外部调用。** 决策请求、策略/提示/模型配置、调用预算与全部结果必须可追溯；Runtime 独立检查结构和选项成员关系。非法输出、弃权、超时、取消、传输错误与调用结果未知分别记录。恢复使用已持久化的选择；外部调用是否完成不明时保留 unknown，不自动再付费调用，也不派发执行器。记录足以重建当时输入和已观察结果，不承诺托管模型逐字重现。

**工程验收与收益验收分别结论。** 合同、预算、恢复和旧行为回归由无凭据 CI 验证；收益由预先冻结的开发/验证切分、固定规则基线、单一 LLM 配置和独立产物裁判验证。未调用真实模型时只能报告工程验证结果。实验允许得出“收益未证明”，不会为了通过而更换验证集、降低门槛或反复挑选模型。

**M3 复用证据，不继承实验结论作为授权。** 本轮沉淀上下文、选择、失败和最终验收的关联记录；M3 再从冻结的开发经验提出 Policy 候选，并在新的独立验证集上评估。首个 LLM 实验不自动形成 eligible Candidate，不修改默认 activeGenome。M3 仍以真隔离、裁判独立晋升和独立评估预算为前置；规则策略同样可以经验驱动演化，LLM 收益不是 M3 的硬前置。

考虑过直接让编码 Agent 同时规划、执行、总结并调整策略；这样难以区分收益来源，也容易让候选控制裁判。也考虑过先绑定 Jev 或启动微调，但当前尚无足够数据和比较基线。此次只实现一个真实 LLM Adapter；Jev 等实现以后复用同一合同另做比较，不同时预建多个模型后端。

代价是需要补齐决策调用记录、上下文快照和独立调用额度，并维护实验 fixture。收益是在线决策与离线演化拥有可检查的接口和证据边界。实验参数、切片、失败场景、报告格式及 M3 交接要求以[实施与验证规范](../experiments/organism-decision-v1.md)为准；M3 的具体学习算法与晋升协议升级待实验收口后另写 ADR 0008。

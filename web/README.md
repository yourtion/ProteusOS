# Proteus 本地代码工作台

在仓库根目录执行 `pnpm web:build`，再执行 `pnpm web`（或 `pnpm proteus web`）。打开终端打印的完整地址完成会话认证，地址中的启动令牌随后被移除。服务仅监听 `127.0.0.1:4310`，默认使用独立实例 `.proteus-web/`。`pnpm proteus web --home <目录> --port <端口>` 可以指定实例和端口。

## 使用流程

1. 在“项目与检查配置”添加 Git 仓库根目录，输入项目名和测试命令的参数数组，例如 `["node", "--test"]`。宿主会冻结该命令；数组为空时结果明确标记未验证。
2. 选择项目，在新任务中描述需求，选择理解、审查或修改代码，选择已启用的执行器、模型、推理强度与超时。执行器列表来自宿主配置，支持 `~/.proteus-local/executors.config.mjs` 中的本地适配器；模型和强度受执行器配置与协议能力约束。执行器需在宿主机完成相应认证；“已安装”只代表适配器安装状态。
3. 观察执行过程并处理一次性权限请求。任务准入后立即返回，Host 串行执行；刷新和关闭浏览器不取消任务。停止必须显式点击“请求停止”。
4. 在右栏查看文件修改前后内容、独立测试输出和运行证据。总结按文本呈现，不执行模型返回的 HTML。
5. 审阅后点击“应用到原项目”并确认。系统核对全部已纳入文件的基线，再写入修改；原项目已变化时拒绝覆盖。重复应用返回原回执。中断的多文件应用有备份恢复入口，额外修改冲突时保留备份等待人工处理。
6. “补充需求”会以已有结果为输入副本启动关联的新 Run；不声称续接外部 Agent 的原会话。证据页可下载结果 JSON。

## 运行语义

任务与请求幂等回执在同一 SQLite 事务准入；同一请求 ID 的内容改变会被拒绝。SSE 首次发送权威快照，之后发送带序号和基准游标的字段增量。浏览器通过 Last-Event-ID 重连，在内存窗口内补发；游标过期、服务重启或频道被淘汰时重新发送快照。公开活动和权限请求持久化。最多保存每 Run 2000 条公开活动，另保留终态；文本片段合并并按 4000 字符分段，工具参数/输出有界展示并遮蔽常见凭据字段。丢弃计数单独显示。SSE 每 250ms 检查变化，15 秒心跳；最多缓存 16 个频道，每频道 32 帧或 1MiB 字符预算。传输游标是临时同步标识，不是持久化审计事件编号。

Host 持有实例锁。该实例的其他 CLI 入口会明确拒绝访问；CLI 的 `web` 命令使用同一 Workbench 应用模块。Host 启动时恢复 pending 工作，对已派发但未确认的执行沿用 Runtime unknown/对账语义，不自动重发。旧权限回调过期，不能通过重启后点击旧请求继续授权。

测试命令使用异步子进程，在独立副本内运行；超时或停止终止本地检查进程组。ACP 的停止请求先传递协议取消，必要时终止其本地进程。远端副作用或费用不能据此认定为零。

## 当前范围

- 已接通项目配置、真实 Run 准入和后台执行、Codex/Claude ACP、公开进度、权限待办、取消、结果对账、关联任务、文件前后比较、测试输出、基线冲突检查、应用/恢复及结果导出。
- 首版面向默认个体和本地操作者。经验与行为版本页支持冻结许可经验、规则学习作业、策略候选评价、采用与回滚；写操作带版本检查与幂等回执。验证集登记和分享管理仍使用原 CLI。进程中断后状态未知的行为管理操作不会自动重发，需要人工核对。
- 项目限普通 Git 仓库，执行快照支持文本、二进制文件与可执行权限，最多 2000 个文件、64 MiB，单文件最多 8 MiB。模型文本投影独立限额，默认总计 1 MiB；二进制及超出投影预算的文件显示元数据，仍保留在执行副本。修改前后按字节和权限比较，二进制变更可随审阅后的变更集应用与恢复。依赖、构建产物、常见凭据目录和 `.env*` 不进入输入，排除清单随任务保存；新生成的受限凭据文件会使输出检查失败。子模块、符号链接、未物化的 LFS 指针仍会阻止接入。不会自动安装依赖。
- 任务副本是文件隔离，不是操作系统沙箱。外部 Agent 仍遵循其本身权限机制；请核对工具权限请求。测试命令是用户明确配置的本机程序。
- 没有公网部署、多用户、终端模拟器、内置代码编辑器或 Git 提交/推送。当前文件比较展示完整修改前后文本，未引入大型 diff 编辑器。

## 开发与检查

React + Rsbuild + TypeScript，Hono 负责 HTTP 和 SSE，SQLite 由现有 Storage 管理；沿用 Oxlint、Oxfmt、Vitest。`pnpm web:typecheck` 检查前端类型，`pnpm web:build` 构建静态文件。`pnpm check` 包含前端类型和构建。

`tests/integration/web-workbench.test.ts` 使用临时 Git 项目、真实 SQLite/HTTP/SSE 和受控测试执行器验证主要流程；ACP 合同测试使用真实 ACP 协议的 fixture。浏览器只能选择宿主已启用的执行器，不能上传任意实现。完整测试集中的 model-free 诊断测试需要 Node 26，建议使用 Node 26 运行全部检查。

真实页面回归使用独立 Playwright 浏览器：

```sh
pnpm install
pnpm exec playwright install chromium
pnpm test:web
```

已安装 Microsoft Edge 时，也可以执行 `PROTEUS_BROWSER_CHANNEL=msedge pnpm test:web`。脚本创建临时 HOME、本地适配器配置、空数据库和两个 Git 项目，经实际 CLI 启动 Web；通过页面操作验证任务、权限、模型与强度传递、检查、应用、重试、跨项目切换及重启恢复。ACP 服务是受控协议 fixture，不会调用真实模型。报告和截图保存到 `artifacts/web-browser/`，不包含启动令牌；Ubuntu CI 执行该回归并上传证据。详见 [验收记录](../docs/web-workbench-validation.md)。

## DSH 组件复用

核对 `deepseek-harness` 提交 `5badb15009ae1756c3afe0ae0cef1faafc290ccc`。DSH 的 Web 入口使用 React 18/Vite，本项目使用 React 19/Rsbuild。构建器不是普通组件复用的主要障碍；需逐项验证 React 版本、CSS 变量及内部依赖。

`ui-primitives` 中 Input、DisclosureRow、SegmentedControl、DiffBlock 是可参考候选，但发布包仍声明 Cordis peerDependency，并使用内部 store、代码语言和工作区路径工具。完整 ui-layout、ui-chat、ui-workspace 依赖 Slots、Context 和 Host/Client 投影。当前界面借鉴其项目与任务的信息布局，自行实现组件，没有复制 DSH 源码；以后提取组件时需保留 MIT 许可证与版权声明。

## 对话、工具和用量

右栏提供工具、Trace、用量页。工具按 toolCallId 合并状态，保留可用输入/输出；Trace 展示执行器公开轨迹、进度、覆盖范围和丢弃计数。执行证据随 Work 保存，因此旧任务没有的证据不会伪造回填。

Claude 启用现有 SDK 数值回执采集，展示输入/输出、缓存读取/写入及完整性；SDK 费用只是未核对估计。Codex 或其他没有可靠消耗字段的执行显示未知。ACP usage_update 是上下文占用，不计入累计消耗。公开计划可显示，私有推理块不进入这些投影。

补充需求可查看最多 30 轮祖先记录，给新执行器传入最近最多 8 轮的有界摘要（总上限 8000 字符）与上一轮文件结果。它不是恢复同一 ACP session，也不保证完整原始对话都进入模型上下文。

Conversation、Turn、Run 已分开持久化；后续任务继承会话并记录父 Turn，旧任务启动时按祖先关系补齐标识。侧栏按会话分组，`GET /api/conversations` 可读取完整轮次关系。准入和幂等回执在同一事务内写入。

DSH 对齐的后续范围：持久化事件日志、会话/子调用关系、事件来源与替换链、ACP 会话恢复能力协商、跨轮用量聚合。当前不能宣称完整 DSH Trace 对齐。

## 连续阅读体验

任务页现在将祖先轮次的问答总结、当前需求、公开执行过程和最终回答放在同一阅读区。工具状态按调用 ID 原位合并；历史轮次仍是总结，不伪装成完整消息回放。Markdown 支持段落、列表、表格、引用、代码块与复制；原始 HTML 显示为文本，图片不自动加载，只有 http/https 地址成为外链。本轮相对文件链接可跳转已记录的变更文件，其余路径显示不可用提示。

选中的任务、过程折叠状态与滚动位置在当前浏览器标签会话中保留。执行时跟随最新进度，向上阅读后停止跟随，提供“回到最新进度”。`src/app/workbench/transcript.ts` 定义公开阅读节点及确定性投影（message/plan/tool），供后续持久化事件层复用；它本身不是原始 ACP 日志或不可变审计记录。

## 紧凑执行摘要

每轮使用一张横向执行卡：状态、已记录工具次数、观测耗时、Token 与 Trace 入口放在同一行，下方展示首次观测顺序的前 5 个调用，其余通过“+N 次”进入工具列表。调用顺序不是并行依赖图，也不表示全部调用串行执行。耗时优先使用执行器进度，否则取公开事件首末跨度；缺失用量显示未报告，部分用量和截断明确标注。

卡片默认收拢，展开后在工具、轨迹、进度之间切换；点击摘要里的工具直接展开对应输入输出。右侧变更/证据面板按需打开，模型、推理强度和超时收在更多设置中。正文保持 16px，紧凑度来自间距、分组和按需展示。手机宽度下指标自动换行、工具输入输出变为单列。

组件检查：`pnpm web:test`（React 服务端渲染断言），已纳入 `pnpm check`。这些测试验证内容和状态，不代替浏览器布局与交互验收。

## 统一界面与组件边界

各页面共享暖白底色、陶土色主操作与语义状态色。正文 16px、控件 14px、辅助信息 12–13px；紧凑布局主要通过行式列表、统一间距和折叠详情实现。

- `src/ui/`：按钮的提交/等待行为、标签与提示关联、页面标题、分区、状态标签、提示、空状态、证据披露与键盘可切换的分段选择。任务、作业和执行卡使用同一状态字典；未知状态保持中性。
- `src/styles/tokens.css`：颜色、字号、间距和圆角的共同入口。`components.css` 负责共享组件；`layout.css` 负责工作台与详情栏；`conversation.css` 和 `execution.css` 分别负责对话与执行过程。`style.css` 仅组合这些文件，避免在末尾重复追加覆盖。
- `src/pages/Projects.tsx`、`src/pages/Settings.tsx`、`src/TaskInspector.tsx`：按页面或任务边界管理展示与局部交互。项目表单草稿留在项目页，保存状态仍与工作台共享，避免保存期间切换项目造成响应覆盖。
- `src/api.ts` 与 `src/models.ts`：共享请求错误语义与前端投影类型。版本检查、请求幂等、任务准入与 SSE 仍沿用服务端协议；不额外引入全局状态库或新的组件依赖。

`pnpm web:test` 覆盖共享控件语义、项目/设置/行为版本加载状态、六类详情视图、应用入口约束，以及执行卡内容。浏览器脚本已适配高级设置与详情折叠入口；组件渲染检查不验证布局、焦点移动和真实点击流程，需要单独运行页面验收。
